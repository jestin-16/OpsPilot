### Step 4: Register Continuous Deployment Runner (One-Time Setup)
This allows GitHub Actions to deploy to this machine automatically whenever
code is pushed to main.

1. Open your browser and navigate to:
   https://github.com/jestin-16/OpsPilot/settings/actions/runners/new?arch=x64&os=win
2. Copy the token generated under the "Configure" section.
3. In PowerShell, run:
   .\scripts\setup-self-hosted-runner.ps1
   (Paste the runner token when prompted).

Manual Alternative (if running directly):
mkdir C:\actions-runner -Force
cd C:\actions-runner
Invoke-WebRequest -Uri https://github.com/actions/runner/releases/download/v2.322.0/actions-runner-win-x64-2.322.0.zip -OutFile actions-runner.zip
Expand-Archive -Path actions-runner.zip -DestinationPath . -Force
Remove-Item actions-runner.zip
.\config.cmd --url https://github.com/jestin-16/OpsPilot --token <YOUR_RUNNER_TOKEN> --name "opspilot-host-laptop" --work "_work" --labels "self-hosted,windows,x64,opspilot-prod" --unattended --replace
.\svc.cmd install
.\svc.cmd start

Verify the runner service is active:
Get-Service -Name "actions.runner.*"

### Step 7: How Future Deploys Work
Whenever code is pushed or merged into the main branch:
1. GitHub Actions runs the CI test suite across all 7 Spring Boot microservices
   and the React frontend.
2. The deploy-to-host job activates the self-hosted runner on this machine.
3. The runner executes docker compose up -d --build, performs a health check,
   and prunes dangling images with zero downtime.
